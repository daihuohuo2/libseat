# 座位助手 · 安卓体验版 0.1.0

手机独立运行，无需电脑开机。构建后生成安装包：`output/seat-assistant-0.1.0.apk`。GitHub 源码仓库不包含预编译 APK 或本地签名密钥。
最低 Android 8.0，建议更新 Android System WebView。当前为本地签名的侧载体验版，尚未发布应用商店。

## 手机上体验

1. 将 APK 发到手机，在文件管理器中打开，按系统提示允许此次安装。
2. 打开应用，可先点顶部“体验演示”。演示提供 48 个模拟座位，支持观察、方案与模拟预约，不会向学校提交请求。
3. 点“返回真实模式”，进入“登录管理 → 登录学校账号”，在学校官网页面完成登录。
4. 选择区域、加入抢选名单；地图下方“详细配置”可修改日期、时段和轮询间隔。
5. 默认勾选“仅观察空位，不提交预约”。需要真实预约时自行取消勾选，再开始任务。
6. 任务运行时有常驻通知，可在通知栏停止。成功结果会保存在运行记录中。

演示与真实模式的配置、预约记录各自独立。安装包不含电脑上的账号、登录令牌、Cookie、历史记录或浏览器资料。

## 本版边界

- 已接入：原有座位查询、区域与方案、预约引擎、时段检查、失败核实、记录保存、防重复提交、手机通知、原生文件选择器导入/导出方案。
- 学校登录使用独立 WebView，在官网完成验证后读取本站登录令牌；不会读取密码。学校 CAS 会话仍有效时可尝试静默续期，失效后需重新登录。
- 尚未完成本人学校账号的真实登录、地图数据与真实预约端到端测试。学校网络、登录页面或接口变化可能需要进一步适配。
- 超时核实保留电脑版机制；目前仍依赖官网特定预约记录模块，无法核实时会保留待确认状态并阻止再次预约。
- 后台采用 Android dataSync 前台服务及任务期间的唤醒锁。系统省电、厂商后台管理、断网、强制停止和系统运行时限仍可能中断任务，不能保证整夜持续运行。
- 系统终止后，重新打开不会自行恢复抢座；未确认的提交会先尝试核实。应用不申请开机自启。
- 界面沿用电脑版：地图用于展示座位状态，不支持在地图上直接点选座位。

## 架构

`prepare-assets.js` 用明确白名单打包现有网页与业务模块。桌面文件不做修改。

- `EngineService`：独立 WebView 运行现有 `server.js` 等模块，原生适配 HTTP、AES、文件与定时器；不监听本地 TCP 端口。
- `MainActivity`：本地网页界面、原生文件选择器、学校登录界面。
- `web/engine-runtime.js`：有限的 Node API 兼容层，保留原有预约状态机。
- 所有账号与预约数据放在应用私有目录，禁用系统备份；真实与演示目录隔离。
- 有权限的 WebView 只加载打包页面，使用 CSP 限制脚本与框架；学校页面没有原生 JavaScript 桥。网络请求只允许学校预约 HTTPS 主机，证书异常不会被忽略。

## 构建

需要 JDK 21、Node.js、Android SDK（API 36 或以上平台及 build-tools）。不依赖 Gradle 或额外 npm 包。

```powershell
./build.ps1 -Sdk D:/Android/Sdk -Java D:/Java
```

输出 APK 使用项目本地 `local-debug.keystore` 签名。保留该文件才能继续覆盖安装同一签名版本；不要把它作为正式发布密钥。构建脚本首次运行自动生成体验版密钥。

## 目录结构

- `src/`：Android 页面、前台服务与本地资源加载。
- `web/`：移动界面适配、共享引擎兼容层和应用内体验演示。
- `res/`、`AndroidManifest.xml`：应用图标与系统声明。
- `prepare-assets.js`：准备网页资源并打包共享业务模块。
- `build.ps1`：编译并生成体验版 APK。
